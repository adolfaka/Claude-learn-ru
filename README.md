# Claude Code practice

Репозиторий для практики к руководству [Claude Code: Everything You Need to Know](https://github.com/runowata/claude-code-ru). Уроки лежат в руководстве; в этом репозитории находятся небольшое приложение, на котором вы тренируетесь, и проверка для каждого основного урока и итогового проекта.

## Старт

1. Нажмите **Use this template** > **Create a new repository**, чтобы сделать свою копию, и клонируйте её.
2. Либо откройте свою копию в Codespace: Node.js, Claude Code и зависимости песочницы (sandbox) уже установлены.

Нужны Node.js LTS и git. Через npm ничего устанавливать не надо: приложению и проверкам хватает самого Node.js.

## Учитесь шаг за шагом

Запустите учебное приложение в одном терминале, а Claude Code используйте во втором терминале рядом:

```bash
npm run learn
```

Оно показывает по одному шагу урока, следит за вашей копией и подсвечивает шаг зелёным, как только ваша работа на месте. Каждый раз, когда навык встречается снова, помощи становится меньше: сначала показана каждая команда, потом подсказки, потом только цель. В приложении есть все уроки всех трёх уровней — начального, среднего и продвинутого, — включая итоговый проект каждого уровня. Начиная с урока 2, урок открывается одним вопросом-разминкой из прошлого урока, если раньше вы ошиблись в вопросе на его навык. Помощь убывает внутри каждого уровня: каждый урок после первого урока уровня рассчитан на меньшую помощь, чем этот первый. Пропущенный урок не учитывается, поэтому навык из него может вернуться с большей помощью. Карта уроков показывает по одному уровню на странице.

- Клавиши: стрелки или цифры, чтобы выбирать, `enter`, чтобы идти дальше, `h` для подсказки, `m` для карты уроков, `q`, чтобы выйти. Ваше место сохраняется в `.practice/learn.json`.
- Если PowerShell отказывается запускать `npm`, выполните `npm.cmd run learn`.
- Странные символы или цвета? Задайте `LEARN_PLAIN=1` (в PowerShell: `$env:LEARN_PLAIN=1`) перед `npm run learn`. Приложение также учитывает `NO_COLOR`.
- Нужен неподвижный экран? Запускайте `npm run learn -- --calm` или задайте `LEARN_CALM=1` так же, как `LEARN_PLAIN`.
- В приложении нет ИИ, и оно не меняет вашу работу: оно читает ваши файлы, запускает проверку урока и команды git, которые ничего не меняют (`git status`, а также узнаёт, является ли рабочая папка репозиторием, который игнорирует `.practice/`), и записывает только свой собственный файл.

Начиная со среднего уровня, уроки предлагают практиковаться в одном из ваших собственных репозиториев. У каждого следующего уровня своя рабочая папка; пока вы не выбрали другую, это ваша учебная копия:

- Нажмите `f` на странице уровня в карте уроков или на проверке урока и введите либо вставьте путь к папке. Карта показывает папку каждого уровня. Первый урок уровня, который вы открываете в приложении, тоже спрашивает о ней, пока у уровня нет папки.
- Чтобы выбрать папку заранее, запускайте `npm run learn -- --dir <path>` с путём относительно этой копии или полным. Так задаётся рабочая папка уровня, на котором откроется приложение.
- После этого приложение проверяет, следит и запускает `git status` в этой папке и говорит, в какой папке выполняется каждый шаг.
- Итоговый проект среднего уровня всегда выполняется в этой копии. Урок 5 и итоговый проект продвинутого уровня выполняются в новой копии шаблона: каждый из них спрашивает папку этой копии — это не может быть текущая копия — и ничего не проверяет, пока вы её не укажете.
- Ваш прогресс хранится в этой копии, поэтому запускайте `npm run learn` отсюда. Вместе с ним сохраняются только выбранные вами папки.

## Проверьте свою работу

Каждый основной урок и каждый итоговый проект заканчивается проверкой. Запускайте её из корня своей копии:

```bash
npm run check -- b-1
```

Каждый пункт печатает `PASS` или `FAIL` с подсказкой, что исправить. Чтобы проверить урок, выполненный в одном из ваших собственных репозиториев, выполните ту же команду из своей копии с `--dir` и путём к этому репозиторию, относительным от вашей копии или полным. Здесь это папка рядом с вашей копией:

```bash
npm run check -- b-1 --dir ../my-project
```

Некоторые пункты читают файл, который вы сохраняете в `.practice/`, для состояния, существующего лишь мгновение, например план до его одобрения. Git игнорирует эту папку, поэтому такие пункты проверяются только на вашем компьютере.

## Следите за прогрессом

- Каждый push запускает workflow **Progress**, который выводит результат каждой проверки в сводке запуска. Он никогда не падает: незавершённое упражнение отображается как «пока нет», а пункты, читающие `.practice/`, — как «проверено локально».
- Откройте issue по шаблону **Отслеживать прогресс**, чтобы получить чек-лист по каждому уроку и итоговому проекту.
- В ветке `solutions` [шаблона](https://github.com/wesammustafa/claude-code-practice) лежит эталонное решение для каждой проверки. Читайте его после честной попытки.

## Приложение

Небольшая программа для проверки ссылок в Markdown. Она сообщает об относительных ссылках, файл которых отсутствует:

```bash
npm run linkcheck -- samples
npm test
```

Приложение — это `src/`, `test/` и `samples/`. Остальное относится к курсу: в `checks/` лежат проверки, в `learn/` — пошаговое учебное приложение, в `capstone/` — задания итоговых проектов, в `.github/` — workflows. Workflow **Assert checks** работает только в репозитории шаблона: в вашей копии его задание пропускается, и GitHub показывает это как пропущенную проверку, так что вы можете коммитить упражнения в любую ветку, включая `main`.

## В Codespace

- Dev Container Feature для Claude Code всегда устанавливает последнюю версию Claude Code ([Dev containers](https://code.claude.com/docs/ru/devcontainer)). Руководство проверено на релизе `stable`, который совпадает с ней или старше, так что уроки по-прежнему применимы.
- Если вход через браузер завершился, а терминал всё ещё ждёт, скопируйте код, который показывает браузер, и вставьте его на запрос `Paste code here if prompted` ([Dev containers](https://code.claude.com/docs/ru/devcontainer)).
- Если команды в песочнице падают с `Can't mount proc on /newroot/proc: Operation not permitted`, контейнер блокирует собственное монтирование `/proc` песочницы. Обойти это можно, задав `sandbox.enableWeakerNestedSandbox` значение `true`, но делайте так, только когда контейнер уже обеспечивает нужную вам изоляцию ([Sandboxing](https://code.claude.com/docs/ru/sandboxing)).
- Время вычислений в Codespaces учитывается во включённом лимите вашего аккаунта GitHub ([Codespaces billing](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces)).
