## intro
- minutes: "около 20 минут"
- why: "Закройте `.env` от Claude для всех, пусть тесты идут без запросов, а push сначала спрашивает."
- can: "выбрать узкое правило разрешений, положить его в файл настроек нужного уровня и проверить границу песочницы."
- payoff: "выбрать узкое правило разрешений, положить его в файл настроек нужного уровня и проверить границу песочницы."
- read: "[Making Claude Code more secure and autonomous with sandboxing](https://www.anthropic.com/engineering/claude-code-sandboxing): почему у песочницы есть граница файловой системы и граница сети."
- need: "В Linux и WSL 2 для песочницы нужны `bubblewrap` и `socat`"
- need-repo: "Один из ваших репозиториев с командой запуска тестов — для раздела „Ваша очередь“; либо используйте учебную копию для обоих целей."

## ladder

### закоммиченный `.claude/settings.json` запрещает читать файлы `.env` и разрешает узкую команду запуска тестов
- narrow "не закоммичен. Выполните": git status по-прежнему показывает файл настроек как новый или изменённый?
- narrow "Нет файла .claude/settings.json": Сохранён ли файл по этому пути в той папке, которую читает проверка?
- narrow "некорректный JSON": Не пропущена ли рядом с правилами запятая или скобка, или нет ли лишней?
- narrow "Замените каждый TODO": Вы снова закоммитили файл после того, как заменили все TODO?
- narrow "Добавьте `Read(./.env)` в": Называет ли одно из правил deny сам файл .env, без ничего после него?
- narrow "Добавьте `Read(./.env.*)` в": Покрывает ли второе правило deny файлы, чьи имена начинаются с .env и точки?
- narrow "пропускает любую команду или любое использование инструмента": Не пропускает ли правило allow целую программу или инструмент вместо одной команды тестов?
- narrow "Добавьте правило allow": Есть ли правило allow для команды, которая запускает ваши тесты?
- hint: "Закоммиченный `.claude/settings.json` запрещает чтение файлов `.env` и `.env.*` и разрешает одну команду запуска тестов"
- back: Y1 Проверьте общие правила здесь.

### закоммиченный `.claude/settings.json` спрашивает перед командой, которую коллеги одобряют каждый раз, например `git push`
- narrow "как корректный JSON с правилом ask": Закоммичен ли файл настроек и разбирается ли он по-прежнему после того, как вы добавили правило ask?
- narrow "Замените TODO в `permissions.ask`": Вы снова закоммитили файл после того, как заменили TODO в правиле ask?
- narrow "Добавьте правило ask в `permissions.ask`": Стоит ли правило для push в ask, а не в deny, и есть ли оно вообще?
- hint: "Если не прошёл пункт про ask, добавьте правило в `permissions.ask`, а не в `deny`: правило deny заблокировало бы нужный вам push."
- bottom: "git show HEAD:.claude/settings.json | jq .permissions"
- back: Y1 Проверьте общие правила здесь.

### песочница включена, а `.claude/settings.local.json` не попадает в git
- narrow "закоммичен, но в нём ваши личные настройки": Не попал ли ваш личный файл настроек в коммит вместе с общим?
- narrow "некорректный JSON": Не оставила ли ручная правка файл настроек, который больше не разбирается?
- narrow "Песочница выключена": Переопределяет ли ваш личный файл общее включение, или её не включает ни один файл?
- hint: "Если не прошёл пункт про песочницу, вернитесь к шагу 3 раздела „Ваша очередь“ в том репозитории, который читает проверка; локальное выключение побеждает общее включение."
- back: Y3 Проверьте итоговую настройку песочницы.
